## 2. Архитектура передачи контекста и промпт-стратегия

### Модель оркестрации: State Machine + Structured Outputs
Агент не просто отвечает текстом, а выступает **контроллером состояния живой доски**.

1. **Входной контекст (Input):**
   - Полная или скользящая история сообщений чата (кто автор, роль, текст);
   - Текущее состояние доски (`current_board_state` в JSON).
2. **Системный промпт агента-фасилитатора:**
   - Роль: беспристрастный фасилитатор команды, связывающий разнородные требования участников в согласованное решение;
   - Задачи:
     - Распознавать мотив и цель каждого автора реплики;
     - Находить скрытые противоречия (например, конфликт между сроками и качеством, бюджетом и масштабом);
     - Не склеивать всё насильно, а предлагать реальные компромиссы;
     - Вести и обновлять карту задачи.
3. **Выходной формат (Strict JSON Schema):**
```json
{
  "task_goal": "Согласованная цель задачи",
  "conflicts": [
    {
      "id": "c1",
      "parties": ["Маркетолог", "Разработчик"],
      "title": "Сроки запуска vs Стабильность сервиса",
      "description": "Маркетинг требует релиз завтра, разработка настаивает на 2 неделях тестирования",
      "severity": "high"
    }
  ],
  "agreed_decisions": [
    "Формат MVP утверждается без сложного рекомендательного движка"
  ],
  "compromise_plan": [
    {"step": 1, "title": "Запустить промо-лендинг со сбором предзаказов"},
    {"step": 2, "title": "Рекомендации формировать по статическим правилам (готовые наборы)"},
    {"step": 3, "title": "Полноценный биллинг выкатить через 2 недели"}
  ],
  "open_questions": [
    "Какой бюджет выделяется на первый этап промо?"
  ],
  "agent_intervention": {
    "needed": true,
    "message": "Команда, вы предлагаете разные пути решения. Предлагаю компромисс: собираем лиды завтра через промо-лендинг, а систему биллинга выкатываем планово. Это устроит и маркетинг, и разработку?"
  }
}
```

## 3. Разделение работы между человеком и AI

- **Где работает человек:**
  - Определение бизнес-правил и структуры интерфейса (Александр, Арина);
  - Формирование сценария и драматургии демонстрации на защите (Александр-спикер, Ева);
  - Контроль логики фасилитации и отсечение галлюцинаций.
- **Где работает AI:**
  - Семантическое сжатие хаотичной переписки;
  - Поиск скрытых нестыковок и зависимостей в требованиях;
  - Мгновенная перестройка доски решений в реальном времени.

---

## 4. Верификация результатов и надежность демо

- **Контроль формата:** Использование режима `json_object` / Pydantic моделей для исключения синтаксических ошибок в JSON.
- **Fallbacks:** В случае задержки сети или сбоя API фронтенд сохраняет последнее стабильное состояние доски и показывает уведомление.
- **Тестовые сценарии:** Набор заготовленных веток дискуссий для гарантированной демонстрации на защите.

---

## 5. Границы применимости AI

- **Где AI дал максимальный буст:** Мгновенный синтез 20 разрозненных реплик в лаконичную карту решения из 3 шагов.
- **Где потребовалось вмешательство человека:** Точная калибровка порога вмешательства агента (агент не должен спамить на каждое мелкое сообщение, а включаться только при обнаружении противоречия или формировании решения).
